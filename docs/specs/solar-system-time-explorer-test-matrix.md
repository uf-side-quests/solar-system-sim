## How to Use This Matrix

Every binding statement in the functional specification has one requirement identifier.
Each row maps that identifier to a verification method and an initial acceptance test.
The matrix records only requirements with direct executable or review evidence as Implemented.
Unverified requirements remain Pending even where part of the behavior is visible in the application.

### Verification Methods

| Code    | Method             | Description                                                                |
| ------- | ------------------ | -------------------------------------------------------------------------- |
| **IT**  | Integration Test   | Automated test across the WebAssembly, worker, data, or rendering boundary |
| **E2E** | End-to-End Test    | Automated browser test of observable user behavior                         |
| **PT**  | Performance Test   | Repeatable measurement on defined reference hardware and data              |
| **CR**  | Conformance Review | Evidence review against source, scenario, licence, or scientific contract  |

### Status Values

| Status      | Meaning                                                 |
| ----------- | ------------------------------------------------------- |
| Pending     | Test has not been implemented                           |
| Implemented | Test exists and passes                                  |
| Failing     | Test exists and fails                                   |
| Blocked     | A named dependency prevents execution                   |
| N/A         | Requirement is inapplicable with recorded justification |
